# V1.2 Design — Correction / autocorrect for lightBlue · yellow · red

**Status:** IMPLEMENTED 2026-05-29 (T201). P1+P2+P3 shipped; gates green.
**Date:** 2026-05-24 (ratified 2026-05-29)

## Ratified decisions (supersede the Open Questions below)

- **Q-C / scope:** implement **Full P1–P3** in phased order (P1 info-only first).
- **Q-B / yellow:** **permanent in-page rewrite IS wanted** — a manual "fix wording"
  action writes the authentic mushaf wording into the page DOM and re-verifies to
  green/lightGreen, gated by the swap eligibility rules.
- **Q-A / lightBlue:** **panel/clipboard suggestion ONLY — never inject ref DOM into
  the host page.** lightBlue correction surfaces the resolved/disambiguated reference
  in the panel (copyable); it does NOT call `placeRefMarkers` or otherwise edit the
  page. (This overrides the "ref-insert" / `text-replace`-sibling framing for
  lightBlue in §1 below.)
- **Q-D / autocorrect set:** **orange** (today), **lightBlue** (only when the ref is
  unique or context-disambiguated), and **yellow** may autocorrect. **red never.**
  Because lightBlue is suggestion-only (Q-A), its "autocorrect" means auto-resolving
  and surfacing the suggestion in the panel without a manual trigger — still no page
  edit. yellow autocorrect performs the gated text-replace automatically.

## Goal

Today only **orange** (real verse, wrong reference) is correctable: `correctInPlace`
rewrites the cited reference to the true one and re-verifies into a lightGreen
successor. V1.2 extends the same correct / autocorrect machinery to the other
non-green colors, each with its own correction *meaning*:

| Color | What's wrong | Correction meaning |
|---|---|---|
| orange (today) | text right, **ref wrong** | rewrite the ref → green/lightGreen |
| **lightBlue** | text right, **no ref on page** | *insert* the missing ref → green |
| **yellow** | text **nearly** right (word-level drift) | show the diff; optionally fix wording → green |
| **red** | citation signal, text not found | suggest a near-match if one exists; else mark unfixable |

## What the verifier already gives us (no new matching needed for the common cases)

From `js/background.js` `verifyFragment*`, a `VerificationResult` already carries:
`matchedRef`, `matchedRefs[]` (all places the text occurs), `authenticText`
(full ayah), `authenticExcerpt` (excerpt-shaped authentic wording), `deviation`,
`matchType`. So:

- **lightBlue** already knows its true ref(s) (`matchedRef` / `matchedRefs`).
- **yellow** already knows the matched ayah and a diff *count*
  (`wordLevelCompareSingleAyah`). It does **not** yet return the *aligned* diff
  (which words missing / extra / substituted) — that's the one new verifier output.
- **red** has `matchType: 'none'`. A near-match needs a fuzzy global probe (we
  already have `wordLevelMatchGlobal` / soft-subsequence helpers to reuse).

## Per-color design

### 1. lightBlue → green (insert the missing reference)

**Mechanism.** Unlike orange (edit an existing ref marker), lightBlue has *no*
ref on the page, so the correction **inserts** a ref marker immediately after the
highlighted ayah span (e.g. ` (البقرة:255)`), then re-verifies as if the ref were
cited → green/lightGreen successor (FR-022).

**Disambiguation (the user's "describing parts of a nearby ayah" case).** When
`matchedRefs.length > 1`, pick the ref by *context*:
1. If an adjacent finding (previous/next in document order) is green/lightGreen/
   orange-corrected and its surah∈ the lightBlue's `matchedRefs`, adopt that
   surah's ref — the writer cited the ayah once, then discussed its parts without
   re-citing.
2. Else if exactly one `matchedRef`, use it.
3. Else → **manual only** (ambiguous): show the candidate refs in the panel and
   let the user choose; never auto-insert.

**Autocorrect safety.** Auto-insert only for case 1 (context-disambiguated) or 2
(unique). Ambiguous → manual. Insertion must be layout-safe (small inline marker,
same treatment as `placeRefMarkers`).

### 2. yellow → green (show the diff; optionally fix the wording)

Two distinct actions — informational vs. editing:

**2a. Show the diff (default, low-risk, can be automatic).** Extend the verifier
to return an **aligned** word-level diff against the matched ayah:
`diff: [{op:'keep'|'missing'|'extra'|'sub', cited, authentic}]`. Surface it:
- in the panel row (a "النص: … الصواب: …" before/after with missing words shown
  as insertions, extra words struck through, substitutions paired); and
- optionally inline via the existing tooltip.
This is pure information — it never edits the page, so it's safe to compute always.

**2b. Fix the wording in place (manual; gated).** Replace the cited text with the
authentic ayah wording (`authenticExcerpt`) — the same text the swap engine shows
at display time, but written permanently into the page DOM and re-verified → green.
This *changes the author's quoted text*, so:
- **Manual only** in V1.2 (no autocorrect) — the user reviews the before/after.
- Reuse the swap engine's eligibility gate (`js/render/swap.js isEligible`):
  refuse `*`-separated multi-ayah excerpts and ambiguous matches.
- Integrity (Principle I): only ever write the **authentic mushaf text**, never a
  guess — this makes the citation *more* correct, never less.

### 3. red → near-match suggestion, or "unfixable"

**Mechanism.** On demand (or during scan for the panel), run a fuzzy global probe
for red findings (edit-distance / soft-subsequence, thresholded). Then:
- **Near-match found** (e.g. one or two typos): present "هل تقصد …؟ / Did you
  mean …?" with the candidate ayah + ref. Accepting runs the yellow **2b** path
  (replace with authentic text) → green successor.
- **No near-match**: the citation is genuinely not Quran (or too corrupt to
  match). Mark the panel row "لا يمكن التصحيح تلقائيًا / No automatic correction"
  — explicitly *not* an error, just unfixable. Never auto-edit red.

**Autocorrect.** Never. Red is the most dangerous to auto-edit; suggestions only.

## Shared mechanics & schema

- **`correctInPlace` generalizes** to three edit kinds: `ref-edit` (orange, exists),
  `ref-insert` (lightBlue), `text-replace` (yellow-2b / red-accept). Each still
  emits an FR-022 successor with `priorFindingId`, flips to lightGreen on a clean
  re-verify, and persists per FR-024/024a.
- **New verifier output:** aligned word-level diff for yellow (and reused for the
  red near-match preview). One new field on `VerificationResult`.
- **Prefs:** generalize `autoCorrectOrange` → `autoCorrect: { orange, lightBlue }`
  (booleans; both default off). **yellow and red have no autocorrect** — manual
  only. Migrate the old key (orange) forward.
- **Panel:** corrected lightBlue/yellow/red join the "Recently corrected" section
  as lightGreen successors, exactly like orange today.
- **Constitution:** no new highlight color (the five verdicts + lightGreen
  provenance are unchanged); corrections still render lightGreen. Principle III
  intact — orange stays the flagship; this widens the safety net around it.

## Open questions (for ratification)

- **Q-A.** lightBlue ref **insertion** adds DOM content to the host page — acceptable,
  or should lightBlue correction be clipboard/panel-only (suggest the ref, don't
  inject)? (Insertion is the only way to truly "convert to green" on the page.)
- **Q-B.** yellow **2b** rewrites the author's quoted words with the mushaf text.
  Is permanent in-page rewrite wanted, or should yellow stay display-only (swap
  engine) + diff info, with no DOM text edit? (The swap already shows authentic
  text; 2b just makes it permanent + re-verifies.)
- **Q-C.** Should the yellow **diff display (2a)** ship first as a standalone,
  low-risk increment (no editing), with 2b / lightBlue-insert / red-suggest
  following? (Recommended phasing.)
- **Q-D.** Autocorrect scope: confirm only orange + (unambiguous/context) lightBlue
  may autocorrect; yellow + red are always manual.

## Recommended phasing

1. **P1 — yellow diff display (2a)** + **red near-match probe** (panel suggestions
   only, no editing). Pure information; zero integrity risk; immediately useful.
2. **P2 — lightBlue ref-insert** (manual, then context-autocorrect) → green.
3. **P3 — yellow/red text-replace (2b)** (manual, gated by the swap eligibility
   rules) → green/lightGreen.
